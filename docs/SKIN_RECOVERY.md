# Skin resources and repair

The public TFX application and source archives do not include Titanfall 2's original skin payloads. TFX captures verified original data from the user's local game and keeps caches outside those archives. DDS caches hold only the supported material ranges; VTF caches hold the authenticated original common index rather than all archive content. The original index lets a replacement restore the selected weapon's omitted entries while preserving unrelated weapons.

## Public one-click flow

Drop a supported skin into the unified installer. TFX checks the selected skin, the game's official resource metadata, verified local caches and available original sources. After validation, installation starts automatically. When local data is sufficient, caching, resource repair, backup, same-weapon cleanup and installation proceed automatically; a required repair or authorization step is shown in the same flow. DDS original ranges use lossless Brotli only when it reduces storage; earlier uncompressed caches remain readable. Corrupt or old caches are never trusted and can be rebuilt automatically from authenticated local originals. TFX caches the selected weapon family on demand rather than scanning the entire game at each launch.

Existing skins installed by another tool are not treated as originals. Changed original regions need a verified original source. TFX can stage the required official files in a separate cache without running whole-game Steam validation; unrelated weapons are preserved. VTF restoration prefers a verified installed-index snapshot when available. Without one, it restores the small original index first and then identifies the archives actually missing, instead of automatically downloading the entire common VPK set. Surviving complete custom entries are retained. A lost custom skin archive still requires the corresponding skin package; official resources cannot reproduce third-party assets.

When a download is necessary, the application shows the files, download size, free-space requirement and a three-step guide. Keep the game closed, choose **Download and install skin**, then scan the displayed QR code using Steam Guard in the Steam mobile app with an account that owns Titanfall 2. The download, verification, repair and selected installation then continue automatically. A staged download can require another QR confirmation; a single sign-in is not guaranteed. If mobile authorization is unavailable, the user can select a complete original resource folder instead. The game directory and selected package are checked again before every publication, preventing a changed selection from installing an earlier skin.

Steam authorization and actual network transfer require the owning user's participation. Automated and native-renderer fixtures verify the control flow, file selection and recovery invariants; they do not replace a successful real Steam sign-in/download test.

The confirmation panel and the QR authorization panel both display a privacy notice. Users do not enter Steam account names or passwords in TFX. TFX does not upload Steam sign-in credentials to the developer or other third-party cloud services; QR sign-in and ownership verification still require a connection to Steam servers. The download helper uses a temporary isolated local session, with persistent sign-in disabled and temporary authentication data removed after normal completion. TFX does not write passwords, tokens or QR codes to its application logs. This describes TFX's handling of authentication data and does not imply offline Steam authentication.

TFX can also read a separate offline original skin pack without binding it to the original author's game directory. Place `TFX-Original-Skins` beside the portable executable, or in the installed application's `resources` directory. The application pins the exact catalogue SHA-256, verifies each payload's size and SHA-256, and compares the requested DDS resource's Steam metadata fingerprint or authenticates the whole VTF original index against the installed Steam manifest. Changing drive letters or game installation directories does not bypass or invalidate those content checks. A missing pack falls back to the normal verified local source flow; an incompatible or damaged pack is never used as repair data.

The personal test pack contains all 800 supported weapon and related DDS ranges plus the original VTF common index. It can fill the portions omitted from a DDS skin package and restore a missing VTF index automatically. The index contains references, not the VTF skin payloads. If a whole STARPAK or VPK data archive is missing, a complete original archive is still required: the compact pack cannot reconstruct unrelated game assets from skin fragments. Complete archive recovery continues to use verified local sources or the optional selective download.

Pack schema 2 stores DDS payloads by decoded content SHA-256, reuses identical data across resource ranges, and uses lossless Brotli when it saves space. The personal test pack's 771,620,864 bytes of weapon ranges use 416,193,413 bytes of stored payloads (46.06% less); the catalogue and VTF index bring the complete pack to 416,666,044 bytes. The loader decodes only requested ranges and bounds each output to its recorded length before verifying SHA-256. It does not decompress the whole skin pack at application startup. Download or executable sizes depend on the outer packaging compression and are verified separately.

The personal pack is kept outside the public source and application archives. Its game resource content belongs to the game's rightsholders; the repository's source-code license does not grant permission to redistribute those assets. Public distribution of game assets requires an applicable permission from the rightsholders. The application-side loader and its tests contain no original game payloads.

In the tested Steam build, 2,184 unique DDS skin ranges were captured locally. Within that cache, all 42 weapon and associated groups recognized by the current catalogue are covered by 800 ranges (771,620,864 bytes), including all of its pilot weapon identifiers. The remaining cached ranges include pilot and Titan body skins; the cache total is not a count of weapon-only ranges. Four out-of-range Monarch AO positions are incompatible and are rejected; no file recovery can make an incorrect offset valid. This audit is coverage of the declared supported catalogue, not proof of every possible user-created skin.

DDS offsets are tied to five official STARPAK metadata fingerprints. The fingerprints include official file sizes and the contiguous chunk offsets, lengths, and SHA-1 hashes. A changed Steam manifest with identical target resources remains compatible; a changed target or an out-of-bounds position fails before a write. Without an installed Steam manifest the existing checks remain, with layoutVerified=false; TFX cannot claim verified compatibility for arbitrary non-Steam builds.

Missing or truncated stock containers require a complete authentic original source. A truncated container keeps its surviving bytes, fills missing bytes from the verified source, and recovers lost managed DDS skin ranges from verified installation records. A VTF index prefers validated managed snapshots and preserves complete surviving custom records. Unknown irrecoverable custom data is not invented; the related skin package must be imported again.

If no local source exists, an optional filtered download can stage exact official resource files in a separate cache. It does not run Steam full-game validation. See [the optional downloader and its limits](STEAM_RESOURCE_DOWNLOAD.md). Real Steam QR authorization and resource transfer remain user-dependent and were not claimed by offline/fixture validation.
